## 1. 产品是什么，网站给谁看

**咣当 AI影像提供两类影像服务：为组织策划可供个人参与的 AI 影像互动，以及围绕专属需求由团队完成的影片创作。这个 H5 是产品介绍、应用方案与合作沟通窗口，并附带能力体验。**

主要读者是品牌营销、活动运营、企业文化/人力/工会、学校及相关机构的项目负责人；高定业务还覆盖需要人物、家庭、企业或城市故事影片的委托方。网站主要帮助项目方判断“适不适合我的项目、怎么用、交付什么、下一步怎么合作”。上述阅读优先级不取消个人委托创作或 C 端参与场景。

| 产品 | 核心定义 | 采购/发起方主要关心什么 | 参与或创作方式 |
|---|---|---|---|
| AI影像馆 | 围绕组织方的品牌、活动或纪念主题，设计多人可分别参与的个人主题影像体验 | 活动目标、人群、主题与品牌呈现、参与路径、成果与使用范围 | 组织方确定项目；参与者选模板，或选身份/场景并编辑行为，形成个人影像设定；真实服务接通后再完成生成与领取 |
| 高定AI影像 | 从真实资料和专属需求出发，由团队沟通、策划、制作并按约定交付影片 | 故事用途、可用资料、表达质量、服务范围、报价和制作安排 | 委托方提需求，团队二次沟通创作；不是自助生成产品 |

网站核心内容是产品能力、具体应用方式、可核实的样品/案例证据、合作过程及需求入口。正式作品只展示已发布且明确授权的素材；方案图、概念图和成片证据保持清楚标识，不把方案承诺当作已实现接口能力。

## 2. 页面职责与主导航

主导航统一为 **首页 / 应用方案 / 能力体验 / 合作咨询**。桌面与手机保持同一顺序与语义，不再用未开放的“我”占用主入口。

| 页面 | 回答的问题 | 主要内容与下一步 |
|---|---|---|
| 首页 `#/` | 这是什么？我该了解哪个产品？ | 简短的 B 端定位、两产品区别与入口；保留精简首屏，不堆叠全部方案与表单 |
| AI影像馆 `#/hall` | 如何把 AI 个人影像用于我的活动？ | 产品定义、客户群、项目方与参与者的分工、应用方案、两种玩法和成果说明；引导方案/项目咨询，能力体验作为演示路径 |
| 高定AI影像 `#/bespoke` | 哪类影片可以委托团队？怎么合作？ | 介绍、样品/方向、按需求报价、需求资料与合作流程；进入咨询，不进入自助生成 |
| 应用方案 `#/works` | 哪个项目场景与我相近？ | 八份方案索引，按两产品区分并直达完整方案；真实作品作为二级证据区，不把参考图瀑布流称为已落地案例 |
| 方案详情 `#/category/:id` | 这个主题具体怎样落地？ | 项目目标、参与者及其选择、选项意义、成果、B/C 价值、准备事项；主动作咨询同类项目，演示入口说明适用范围 |
| 能力体验 `#/experience-center` | 我可以亲自了解怎样的参与方式？ | 模板/自定义直接切换；显示本机设定及真实生成未接入状态，不伪装成已上线活动 |
| 合作咨询 `#/cooperate` | 我的项目怎么开始？ | 产品、方向、来源方案和需求整理；按来源准确返回。当前只能整理/复制，正式接收待接入 |

样片、历史九主题配置与旧个人页均保留兼容路由，作为二级内容。`#/mine` 退出主导航；旧 URL 可恢复，不新增账户或作品管理功能。全局高亮按内容归属：产品内容归首页、方案索引/详情归应用方案、体验配置归能力体验、需求表单归合作咨询；二级样片和兼容页面按实现时确定的父级归属统一，不产生多个同时选中的导航。

## 3. B 端了解与合作路径

推荐路径为：**认识产品 → 找到适用方案 → 看清参与方式和交付成果 → 按需体验能力 → 整理项目需求 → 团队进一步沟通。**

体验是帮助判断能力的可选分支，不是阅读所有方案或联系团队前必须完成的关卡。方案页不同时并列多个等权“样片/新体验/旧配置/咨询”按钮；主要下一步围绕项目合作，其他证据或历史入口降为二级链接。样品为空时，保留清晰状态与返回方案的路径，不用空页中转主流程。

正式咨询未接通前，漏斗止于本机需求摘要；不能声称线索已经入库、团队已收到、已创建订单或将自动联系。接入后是否保留联系人选填、采用何种回复渠道及怎样跟进仍需明确协议。

## 4. C 端能力体验及其边界

保留已确认的两种玩法，而不是增设第三套体验：

- **模板体验**：用户明确选择一整套内容；身份、场景和行为由模板固定。
- **自定义体验**：用户选择身份与场景，选建议行为或在同一文本框编辑“做什么”。

两者共用“内容设定 → 准备素材 → 确认配置”；各模式独立内存草稿，切换不丢失已填内容，刷新清空。照片选填，仅本机预览；成功替换照片需重新授权，失败替换保留旧有效照片；草稿、异步校验、Object URL 回收和复制反馈保护延续。

当前前端只支持设定、照片预览、确认与复制。真实上传、生成任务、进度/失败处理、结果领取、账户、费用和支付未接入。通用体验中心的设定不能当作工行方案的完整活动配置，也不能把它的前端 ID 当作真实生成模板 ID。旧九主题是兼容配置，亦不是独立的第三种新玩法。

保留上层主题“我为品牌代言”，以“与深圳 共成长”为具体示例。建议内容顺序如下；具体文本从用户图中提取并作手机可读排版，不新增未经确认的商业承诺。

| 模块 | 本例说明 |
|---|---|
| 项目目标 | 以深圳与个人成长为共同主题，将品牌客户活动转为可参与的个人影像表达 |
| 发起方与参与者 | 方案中的发起方为工行深圳市分行；参与者为品牌活动客户/普通参与者 |

完整原图作为方案参考资料保留，正文采用可读文字、对应图示与留白。图内示意缩略图不提供假播放；原图中的二维码不变成本地产品的真实体验按钮。通过咨询入口携带“我为品牌代言/与深圳 共成长方案示例”的来源信息；旧数字主题、旧 brand-1 配置保持自己的语义，不冒用新方案参数。

## 6. UI 与交互方向

在现有冷蓝/紫色调和深浅色切换基础上，使用更圆润的容器、克制的层次、较大的留白和清楚的文字层级。参考苹果式简洁与秩序，不复制其标识或产品页面。手机优先，主要动作可辨识；导航、页内索引和表单不过度抢占屏幕。

方案长页应便于跳读，配图与内容对应；同一图片不重复充当每个功能的解释。减少装饰性图标与无意义状态标签，保留真实功能状态、内容性质和必要的错误反馈。亮色和深色分别检查文字/按钮对比、选中态、焦点与固定栏遮挡。

## 7. 已确认事项与仍待明确的业务/接口

**已确认**：B 端介绍为主、C 端体验用于能力展示；两产品分工；两玩法直接切换；工行图为方案示例；高定按需求报价；本次只在本地审阅。

- 正式联系渠道、线索接收接口、负责人、回执和跟进规则；本机复制不是受理。
