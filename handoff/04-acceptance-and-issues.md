# 开发验收与已知问题

日期：2026-10-29。交接基线为精简首页及产品内图文方案；具体发布版本和提交以[交接入口](README.md)与仓库提交记录为准。

**可以据此开展前端实现、问题修订和后端契约设计；当前不是“全部问题已关闭、真实业务可上线”的验收结论。** 2项P1、8项P2保留待修；真实接口与业务缺口另列，不以页面演示替代服务验收。

## 1. 验收顺序与判定

1. 前端先复现本页R01、R02，冻结修复后的预期行为，再补组合路径回归；不要只修改断言使现状通过。
2. 按[页面与路由](01-product-and-routes.md)、[前端行为](02-frontend-behavior.md)实现和核对展示、本机配置、草稿与返回。
3. 后端与现有服务方补齐[接入契约](03-backend-integration.md)后，才开展真实上传、任务、结果、咨询等能力的联调。
4. 对实际首发浏览器或微信WebView做真机验收，最后记录业务方和用户验收。浏览器模拟、GitHub Pages可访问、真实业务通过是不同结论。

以下矩阵中的“验收要求”区分已实现的保护和待修行为；不能因为大部分项通过而忽略R01、R02。

|---|---|---|---|

| A09 | 样片与主题筛选 | 分类入口应保持当前方向，不能继承无关分类；全库浏览与分类浏览应清楚区分 | **未满足：R01待修**；不能把既有筛选保留测试当作分类隔离已经实现 |

## 2. 现有自动检查与盲区

安装锁文件依赖后运行：

```sh
npm ci
npm run typecheck
npm test
```

`npm test`会先构建并更新本地`docs/`，再执行以下六套浏览器检查和一套内容/守卫单测；构建本身不会推送或发布。当前浏览器脚本使用本机Google Chrome路径`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`，其他开发环境需先适配可用浏览器路径。

| 套件 | 覆盖内容 | 不能据此认定的内容 |
|---|---|---|
| [guangdang-ui.mjs](../tests/guangdang-ui.mjs) | 精简首页、双产品8次锚点、八方案、九主题及旧路由、图库6档布局、失败图片和导航 | 不验证R01的“先选校园再进品牌样片”组合；不判断主动作是否符合用户期待 |

| [lightfield-visual.mjs](../tests/lightfield-visual.mjs) | 320/360/390/430：精简首页、图片入口真实触点、原生滚动、32次产品锚点、8场景、暂停/减少动态、分享链接 | 截图和几何通过不等于没有重复图、标签可供性误导或阅读负担；不覆盖所有触屏hover残留 |

六套浏览器脚本支持`PREVIEW_URL`指向同一个已启动的生产构建或在线预览。对指定版本复验时逐套执行，不用只打开首页代替全部路径：

```sh

node tests/guangdang-ui.mjs
node tests/mobile-navigation.mjs
node tests/product-journey.mjs
node tests/lightfield-visual.mjs
node tests/readiness-regression.mjs
node tests/readiness-edge-cases.mjs
```

“上一轮记录通过”“本次提交构建成功”“公开文件与构建一致”“在线浏览器复验通过”需分别记录。本交接页描述覆盖范围与已知问题；本次上传的实际验证结果以[交接入口](README.md)所指的验证记录为准，不能从本页推断用户已验收。

## 3. 未关闭问题：2项P1、8项P2

以下均保持**待修**。R01为可复现的分类状态问题；R02为已复现路径上的主动作调整建议，修改命名/主次前应确定新的产品预期。R03–R10以已测界面为依据，其中阅读负担、误点风险属于专家判断，没有真人误点率或转化数据。

### R01 · P1 · 分类样片串用无关筛选和旧滚动

- **复现**：进入`#/samples/hall?preview=themes`，选“校园青春”并浏览；再进入`#/category/brand`，点“查看样片”。
- **实际**：URL为`#/samples/hall?category=brand`、页头是品牌方向，却仍显示校园筛选及“我的毕业纪念影像/我们的校园记忆”，并恢复旧滚动。精简首页版本定向复核仍存在。
- **修订预期**：按当前分类初始化相关内容；分类与全库的筛选、展开和位置记忆分开；提供明确全库入口。退休纪念不能借用普通职场主题冒充可用退休配置。
- **验收补例**：校园→品牌、品牌→活动、同分类往返、分类→全库、无效分类参数、退休方向逐项核对。修复后新增回归，而不是移除原目录记忆检查。
- **定位**：[Guangdang.tsx](../app/Guangdang.tsx)的`Samples`：`selectedCategory`、`filter`、`themes`与`sampleViews`。
- **证据**：[分类与内容不一致](evidence/r01-samples-filter.png)。

### R02 · P1 · 主“立即体验”先到待开放样片

- **复现**：分别打开`#/hall`、`#/bespoke`，在“立即体验”段点同名主按钮。
- **实际**：均进入“样片制作中”，没有可播放视频；影像馆现有设置库默认收起，高定没有自助主题。
- **建议预期**：影像馆主动作清楚指向已有主题设置预览；高定主动作使用创作方案/整理需求路径。样片未开放状态就近说明，有真实内容后再以观看为主动作。当前不新增生成或假播放。
- **验收补例**：首次访问、来自分类、设置草稿已存在、样片为空/有合规真实内容时分别检查名称与目的页；高定不得出现自助生成承诺。
- **定位**：[MobileEditorial.tsx](../app/MobileEditorial.tsx)的`EditorialProduct`体验段与[Guangdang.tsx](../app/Guangdang.tsx)的`Samples`。
- **证据**：[影像馆待上架目的页](evidence/r02-hall-pending.png)、[高定待上架目的页](evidence/r02-bespoke-pending.png)。

| 编号／级别 | 复现与实际观察 | 建议预期／修后验收 | 代码定位 |
|---|---|---|---|
| R03 · P2 | 手机阅读任一完整方案，页面约5屏以上，设置/合作动作在全文末尾，无章节目录 | 保留完整方案，加轻目录与就近有效动作；跳到选项/成果/价值后标题不被固定栏遮挡，能返回原阅读位置 | `MobileEditorial.tsx / EditorialScenario`、`mobile-editorial.css` |

| R09 · P2 | 320×568打开产品，360px主视觉使四段导航初始位于底部固定栏之后；滚动后可用 | 短高度屏压缩主视觉或前置导航；名称、定义和有效下一步可发现，大手机布局不退化 | `EditorialProduct`、移动端`me-product-hero`样式 |

详细审查依据见[UX_REVIEW_20261029.md](../UX_REVIEW_20261029.md)。建议顺序：R01→R02→R03/R05/R06→其他P2。这里列出建议不代表已批准改变业务能力，也不代表已经实施。

## 4. 业务与接口缺口分开验收

完整编号与事实依据见[DEVELOPMENT_DECISIONS.md](../DEVELOPMENT_DECISIONS.md)，后端工作入口见[接入说明](03-backend-integration.md)。这些事项不记作“前端bug已修复”或“自动测试通过即可关闭”。

| 缺口 | 关闭所需证据 |
|---|---|
| B01 跨方向主题/草稿规则 | 产品明确清除、保留或锁定的策略及返回语义，前后端实现与用例一致 |
| B02 模板与选项映射 | 现有服务方提供真实templateId、选项ID/组合、素材要求和调用约定；不能直接把本地中文或ID当接口参数 |
| B03–B04 授权与真实内容 | 可公开样片/案例、媒体来源与授权依据、上架/下架及业务/主题关联；有真实视频后才验播放器与内容关系 |
| B05 网络内容契约 | 真实列表/详情/分页、鉴权、错误/超时/取消/重试/幂等协议及双方可用环境 |
| B06 正式咨询 | 渠道、承接角色、字段/同意、成功失败回执和重复发送规则；复制摘要不作已提交凭据 |
| B07 照片真实处理 | 上传时机、用途、保存/清理/撤回与错误恢复；本机预览授权不自动覆盖真实生成或公开传播 |
| B08 账户/生成/支付/订单等范围 | 逐项明确本期范围与现有服务协议，真实任务/结果/订单状态有验收证据 |
| B09 首发容器与真机 | H5手机目标已定；补实际浏览器/WebView及系统版本，验真机键盘、返回缓存、读屏和真实链路 |
| B10 退休纪念配置 | 明确是否纳入、真实模板与内容规则、字段及入口条件；保持现有职场主题与退休方案的区别 |
| B11 成果版本与用途 | 每项目确认时长/画幅/字幕/短版/封面是否包含，领取和播放/公开传播/汇总使用范围 |

## 5. 开发交付关闭清单

- 交接时记录提交、构建版本、在线地址与核验结果；源码、静态产物和说明相互对应。
- R01/R02修复后补针对性失败复现与成功回归；R03–R10逐项保留处理结果或明确延期，不能笼统写“UI已优化”。
- 六套浏览器回归、内容单测、类型检查通过；代码变化后只补与变化和风险相关的必要检查。
- 手机H5真机验收和真实服务联调另记结果；未完成的能力继续明确未开放，不用概念图代替样片或客户案例。
- 业务方/用户最终验收状态单独记录，不把工程自测、仓库上传或页面可访问当作最终验收。
