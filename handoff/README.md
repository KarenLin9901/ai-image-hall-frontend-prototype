## 先按这个顺序开工

1. 前后端先共同阅读01，确认产品、分类、主题、方案与作品不是同一层对象。退休纪念方案没有对应配置；高定四类是B端委托，不是自助生成模板。
2. 前端按02还原已确定的页面与状态，优先处理04中的R01/R02；不得把禁用生成或本机需求摘要改成假成功。
3. 后端根据03与B01–B11补齐内容、模板、素材、生成和咨询等纳入范围的服务契约；各能力是否本期接入须先明确。
4. 前后端确认字段和错误/生命周期后，再建立数据适配层，按04联调。真实样片和公开作品须有发布、授权和视频资料。

## 本地启动

已实测Node 22.22.1；依赖以`package-lock.json`锁定。浏览器回归依赖本机Google Chrome，脚本当前使用macOS标准Chrome路径。

```sh
git clone https://github.com/KarenLin9901/ai-image-hall-frontend-prototype.git
cd ai-image-hall-frontend-prototype
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

开发页：`http://127.0.0.1:5173/ai-image-hall-frontend-prototype/#/`。其他系统请按测试脚本调整Chrome可执行文件路径；这不是线上服务配置。

```sh
npm run typecheck
npm test
```

`npm test`会先生产构建到`docs/`，再运行原六套浏览器回归、内容检查和新增主题套件。构建会重写`docs/`，不会自动推送。代码验证、公开原型可访问、真实接口联调与用户最终验收分别记录。

## 当前能做／不能做

能做：按钮切换深浅色、浏览产品与完整策划案、九主题文字设置、本机可选照片预览、复制配置或需求摘要、分享公开页面链接。

未接入：真实照片上传、AI生成任务、正式样片、真实作品、账户、支付、订单、正式咨询发送或跟进。照片与文字草稿只在本次浏览内存保存，刷新清空。

两个P1和四个P2已经登记，仍待修复；各套回归通过不代表所有探索路径已无问题。原型可以用于研发对齐，但不能直接按“业务全部已上线”交付验收。
