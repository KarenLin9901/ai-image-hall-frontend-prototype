## 1. 本轮纠正的理解

用户提供的工行“与深圳 共成长”图片是一份相对完整的**场景策划案内容来源**。用户需要网站提炼其中的目标、玩法、配置、成果与价值，并将这些内容重新设计成手机网页。

- 网站不嵌入整张海报，不使用海报作方案卡片封面，也不提供“查看完整方案图”作为主要内容入口。
- 原图可以保留为项目资料，不能代替网页正文和图文设计。
- 新页面使用真实 HTML 文本、对应的独立场景图片和信息图解；图中的视频缩略图、二维码不变成伪播放或真实活动入口。
- “我为品牌代言”仍是上层主题，“与深圳 共成长”是其中的品牌活动方案示例。它不是已落地客户案例，不声明传播成绩。

本文件覆盖 [08](08-b2b-product-structure-20261101.md) 中“完整原图在页面内作为参考资料展示”的做法，并更新返回、来源记忆与锚点交互约定。08 中 B 端为主的产品定义、两产品分工和服务边界继续有效。

## 2. 已确认的 UI 方向

用户已选择**苹果官网式：大留白、图文叙事、少量卡片**。这次采用这一种呈现方向；不增加产品页面中的风格选择器。

| 区域 | 呈现目标 |
|---|---|
| 首页、产品页 | 先说清产品定义，再用简洁图文解释用途。标题、正文和动作各有层级；减少同屏等权入口及层层卡片 |
| 场景策划页 | 依照阅读顺序分段呈现目标、参与方式、配置意义、成果与价值。独立图片或图解负责说明具体内容，不反复铺同一张参考图 |
| 方案配置示意 | 用清楚的选项和反馈说明“选择意味着什么”。控件较紧凑，选中状态可辨认；不伪装成已经接通的生成器 |
| 能力体验 | 继续使用模板/自定义分段控件，保留分步操作、草稿、素材与错误反馈；系统式控件服务任务完成 |
| 咨询表单 | 让产品、来源方案、当前需求方向和提交状态容易理解。来源与当前选择不矛盾 |
| 全站 | 保留现有色调与深浅色切换；圆角克制、留白充分。主要动作统一，不以透明层、阴影或动效增加阅读负担 |

页面是否接近所选方向，以实际手机与桌面效果判断；增加圆角或改变字体本身不等于完成 UI 改版。

## 3. “与深圳 共成长”需要展示的策划内容

| 内容部分 | 必须讲清的内容 | 读者获得的判断 |
|---|---|---|
| 方案定义与目标 | 以城市成长与品牌陪伴为主题，将品牌客户活动转化为参与者的个人影像表达 | 这是什么活动，适不适合自己的项目 |
| 面向谁 | 品牌/机构为发起方，活动客户及城市生活者为参与者；客户活动、开放日、社群运营等为使用场景 | 谁采购、谁参与、在哪里开展 |
| 活动亮点 | 品牌专属主题、AI影像互动、多场景应用、传播延展；传播是设计用途，不是结果保证 | 产品如何服务活动，而不只是一张照片生成视频 |
| 叙事结构 | 我的初来深圳 → 我的成长 → 工行相伴 → 未来继续向前 | 统一的品牌叙事与个人故事如何结合 |
| 用户配置 | 成长主题选1项；深圳场景选2–3项；服装风格、视频风格、个性文案按需设置 | 能选什么、为何选择、会影响什么 |
| 参与流程 | 扫码进入 → 准备照片并确认授权 → 选择主题与配置 → 形成专属影像 → 保存与自愿分享 | 完整活动拟如何运作；哪些步骤是目前本地演示 |
| C 端成果 | 以本人为主角、带有个人成长和品牌主题的约30秒短片，是本方案的成果目标 | 用户最终带走什么，而不只得到一份配置文字 |
| B 端成果与价值 | 活动主题、参与路径、允许的选项及成果呈现形成统一项目方案，用于组织客户互动与经约定的内容使用 | 公司采购的范围，以及用户故事与品牌主张的关系 |
| 合作准备 | 参与对象、场景、品牌素材、规模、期望成果与使用范围 | 下一步向团队提供什么需求 |

成长主题对应“职场成长、家庭相伴、创业逐梦”；深圳场景对应“深圳湾、福田 CBD、前海、工行网点、城市生活”。个性设置影响人物外观、影片情绪和个人表达。具体活动开放哪些选项、采用什么制作标准和交付方式，仍按项目确认。

30秒、生成、下载和分享在这里属于**活动方案设计**，不代表本地原型已经具备这些服务。品牌素材、交付版本、使用授权、费用和周期不由网页自行承诺。

## 4. 方案配置示意与能力体验的关系

两者解决不同阅读问题，但不增加第三种生成玩法。

| 页面内容 | 作用 | 状态和边界 |
|---|---|---|
| 品牌方案中的配置示意 | 让 B 端项目方理解成长主题、场景组合与个性设置会怎样影响方案 | 本地页面说明。选择仅更新可见示意/摘要，不上传照片、不创建生成任务，不自动改写体验中心草稿 |
| AI影像馆能力体验 | 让读者亲自了解实际参与动作：固定模板，或选择身份/场景并编辑行为 | 保留已有两种玩法、各自内存草稿、素材授权与复制；真实上传/生成未接入 |
| 正式品牌活动 | 按已确认活动模板组织真实参与和成果交付 | 工行示例尚不等于正式上线活动；需要项目范围与后端协议确认 |

如果方案示意提供可点选控件，应明确标为“方案配置示意”，展示成长主题单选、场景2–3项的约束及当前选择反馈。未达到要求时解释缺少什么；达到上限时不能无声替换用户选择。成果说明应跟随选项变化，但不能出现虚假的生成进度或已生成影片。

## 5. 可以直接向用户说明的使用逻辑

### 主线：从了解产品到合作需求

1. **首页选择产品。** 先区分“用于活动互动的 AI影像馆”和“由团队制作的高定AI影像”。
2. **产品页判断是否适用。** 查看服务对象、产品能做什么、交付方式及适用场景。产品页内的“查看应用方案”直接到本页对应方案区，不先去另一个相似列表。
3. **进入具体场景策划案。** 以“我为品牌代言”为例，依次看活动目标、用户选择、选择意义、最终成果和 B/C 两端价值；需要时用段落导航跳读。
4. **结合自己的项目确认需求。** 判断参与对象、活动场景、品牌素材、期望成果与服务范围；高定还可以查看“按需求报价”及报价所需信息。
5. **咨询该项目。** 从方案进入会带上方案来源。填写需求、查看摘要、返回修改；当前原型只能在本机整理与复制，尚未发送给团队。正式沟通、报价、制作与交付是服务接入后的业务流程。

### 可选支线：体验产品能力

在 AI影像馆产品或方案页点击“体验产品能力/查看通用玩法演示”，进入两种玩法：**选固定模板，或自定义身份、场景和行为 → 准备可选照片并确认授权 → 确认设定 → 复制配置**。可以返回原产品/原方案，也可以继续咨询。体验是了解能力的可选步骤，不是咨询前必须完成的关卡。

从全局“能力体验”进入时，应是中性的通用演示，不沿用之前浏览过的品牌方案；从具体方案进入时，来源应保留，咨询与返回均指向该方案。两种入口不能互相污染。

### 高定线：展示、报价与团队创作

**首页选择高定 → 看产品介绍、创作方向和可用样品 → 看报价范围 → 整理咨询需求。** 高定由团队接收需求后再策划制作，不引导用户进入自助生成。样品尚未上架时说明状态，不用空样片页作为必经步骤。

全局“应用方案”保留为跨产品的完整方案库，方便已知道用途的读者直接查找；它不应成为所有产品页 CTA 的重复中转。

## 6. 本轮交互检查发现与修复目标

以下由代码路径检查发现，浏览器复现、修正与最终验证由主执行者记录。表中“修复目标”不等同于已完成。

| 编号 | 当前问题与触发方式 | 修复目标及验收 |
|---|---|---|
| I01 | 品牌方案→体验→首页→全局能力体验，`centerReturn`可能沿用旧品牌；返回与咨询误带来源 | 来源由当前 URL 中的合法 `returnTo` 决定，不再由上次浏览的页面推断。全局入口不附来源，情景入口保留自身来源；原生 Back 使用该条历史记录中的来源 |
| I02 | 产品→样片→返回固定跳`section=experience`，该参数已映射到合作区 | 样品页携带同产品的合法 `category` 时返回对应分类方案；其他情况回产品顶部，不能跳合作区 |
| I03 | 全局合作咨询选择产品后，因缺省`section=experience`，返回跳到未浏览过的产品底部 | 合作选择器的来源单独处理，返回选择器；直达产品咨询默认回产品顶部 |
| I04 | 显式进入价格区后滚到底部离开，再点“查看价格与服务范围”，旧滚动记录覆盖价格目标 | “查看指定段落”始终定位目标；“返回恢复”才读取来源滚动位置，两种动作分开 |
| I05 | 从品牌方案咨询后改需求方向，页头仍显示工行参考方案，但摘要已不包含它 | 可见来源状态与摘要保持一致；明确已切换方向，或清除不适用的引用；不悄悄替换为另一方案 |
| I06 | 产品首屏“查看应用方案”跨页去方案库，而同页同名导航滚到本页方案，语义不一致 | 产品首屏与页内导航统一直接到本页方案；完整方案库仍从全局入口进入 |

来源信息应只包含必要的产品、分类、页面和段落标识，不把个人输入或照片放入 URL。以下约定依据本轮整合代码记录，浏览器表现仍须按第7节回归；不由该记录推定已通过验收。

### 6.1 体验入口与返回地址

新增 [app/experience-navigation.ts](../app/experience-navigation.ts)，集中处理体验中心入口、返回地址及玩法切换。`returnTo` 不是任意 URL，只接受以下站内路径与白名单参数；其他参数丢弃，非法路径回退为通用 AI影像馆来源。

| 合法路径 | 保留内容 | 返回用途 |
|---|---|---|
| `/hall` | `section` 仅接受 `introduction`、`applications`、`experience`、`benefits`；有效段落补充 `restore=1` | 回到 AI影像馆产品来源位置 |
| `/works` | 仅保留 `product=hall`；不带该值时回全部方案 | 回到方案索引 |
| `/category/brand`、`/category/event`、`/category/team`、`/category/campus` | 仅保留合法的 `from=solutions`，其下可保留 `filter=hall` | 回到原 AI影像馆分类方案；后续返回仍可到方案索引 |

- 全局“能力体验”使用 `/experience-center?mode=template`，不附 `returnTo`。它的通用返回是 AI影像馆，不引用上一方案。
- 产品/方案的情景入口通过 `experiencePathFor` 生成地址。体验中心切换 `template` / `custom` 时保留经白名单归一化的来源；来源不随着用户换玩法而消失。
- 历史 `source=brand` 地址继续兼容为品牌方案来源；新入口使用 `returnTo`。
- 具体分类来源的“咨询”带对应方案上下文，通用入口进入 AI影像馆咨询；两者不依赖共享的上一访问页面变量。

### 6.2 产品段落、样品与咨询

- **段落跳转和滚动恢复分别处理。** 产品 URL 显式指定 `section` 时定位对应锚点；仅 `restore=1` 才允许读取该产品的 `view.scroll.current`。有恢复标记且存在记录时恢复原阅读位置，无记录时仍按段落定位。
- **产品首屏“查看应用方案”就地到 `scenes`。** 它与产品段落导航保持一致；全局“应用方案”仍打开完整方案索引。
- **样品返回按可验证来源处理。** 合法且归属于当前产品的 `category` 返回对应分类页；缺失、无效或跨产品分类回当前产品顶部。样品页不再把“返回”固定映射到合作段落。
- **合作选择器有独立来源。** 从全局合作咨询选择产品使用 `source=chooser`，返回 `/cooperate`。产品、方案、主题、样品仍各自保留适用的返回目标；无段落的产品咨询缺省段落为 `introduction`。
- **切换咨询方向取消不适用的方案引用。** 方向不再等于来源方案时，页面明确显示已取消原方案引用，摘要也不包含该方案；不会自动把另一个方案当成参考。带固定主题的历史配置咨询仍要求方向与主题匹配。

### 6.3 方案库的空态

[SolutionGallery](../app/SolutionGallery.tsx) 在尚无已发布且获授权的正式作品时，正常主入口只呈现方案内容，不展示一个注定为空的“正式作品”选项卡。历史 `view=published` 直达地址仍保留明确空态和“查看方案示例”返回入口，不将方案示例冒充正式交付作品。
